## 1. Target MCU

| Property | Value |
|---|---|
| Part | CH32V003J4M6 |
| Package | SOP-8, 3.9 x 5.0 mm, 1.27 mm pitch |
| Core | WCH QingKe V2A, RV32EC, 48 MHz max |
| Flash / SRAM | 16 kB / 2 kB |
| VDD | 2.7–5.5 V (this board runs at 3.3 V) |
| GPIO | 6 |
| ADC | 10-bit, 6 channels on the die (only ~3 bonded ADC pins on SOP-8) |
| Peripherals | 1x advanced timer (TIM1), 1x GP timer (TIM2), 2x watchdog, USART1, I2C1, OPA/comparator |
| Debug / programming | 1-wire SDI on PD1 (`SWIO`), no clock line |
| Chip marking | `CH32V003` / `J4M6` / `E49` (batch/lot) |

Peripheral availability on the SOP-8 variant: **no SPI**, USART and I2C are
available on the bonded pins. Check `TARGET_MCU`/package when writing code.

## 2. Pinout (SOP-8)

```
        +-------------------+
  1 PD6 | o                 | PD1/SWIO 8
  2 VSS |                   | PC4      7
  3 PA2 |                   | PC2      6
  4 VDD |                   | PC1      5
        +-------------------+
```

| Pin | Design name | Default functions | This board |
|---|---|---|---|
| 1 | PD6 | A6 / URX / T2CH3_ / UTX_ | not connected |
| 2 | VSS | GND | GND, C1 |
| 3 | PA2 | OSCO / A0 / T1CH2N / OPP0 / AETR2_ | not connected (crystal pin) |
| 4 | VDD | 3.3 V / 5 V supply | +3.3 V, C1 |
| 5 | PC1 (5 V tolerant) | SDA / NSS / T2CH4_ / T2CH1ETR_ / T1BKIN_ / URX_ | not connected |
| 6 | PC2 (5 V tolerant) | SCL / URTS / T1BKIN | drives Q1 gate via R1 |
| 7 | PC4 | A2 / T1CH4 / MCO / T1CH1CH2N_ | not connected |
| 8 | PD1 | SWIO / AETR2 / T1CH3N / SCL_ / URX_ | WCH-LinkE SWDIO |

### Datasheet caveat (important)

The WCH datasheet (checked v1.3, v1.7, v1.8; both English and Chinese) prints
**duplicate SOP-8 pin numbers** in Table 2-1:

- `PD4 = 8`, `PD5 = 8`, `PD1 = 8` (three pads claim pin 8)
- `PD6 = 1`, `PA1 = 1` (two pads claim pin 1)
- `PC4 = 7`, `PC2 = 6`, `PC1 = 5`, `PA2 = 3`, `VSS = 2`, `VDD = 4` (unambiguous)

An 8-pin package obviously cannot expose PD1, PD4 and PD5 all on pin 8. The
choices used in this repo:

- **Pin 8 = PD1/SWIO.** `PD1` is the only pad whose row is not duplicated, the
  part would be unprogrammable without a bonded SWIO, and community J4M6
  breakout boards (e.g. `mariusmym/CH32V003J4M6-Dev-Board`) wire SWDIO to pin 8.
- **Pin 7 = PC4.** Consistent across all datasheet revisions and community sources.
- **Pin 1 = PD6** (community pinout drawings) — the datasheet also lists PA1 for
  pin 1. Pins 1 and 3 are unused here, so this does not affect this project.

If the chip ever fails to answer `minichlink`, the first thing to test is the
SWIO wire: the alternate reading of the datasheet figure puts SWIO on pin 7
(with PD5 on pin 8). See section 8 for the verification procedure.

## 3. Breadboard circuit

Schematic: [`hardware/schematic.svg`](../hardware/schematic.svg)

| From | To |
|---|---|
| U1 pin 2 (VSS) | GND rail, C1 |
| U1 pin 4 (VDD) | +3.3 V, C1, WCH-LinkE 3V3 pin |
| U1 pin 6 (PC2) | R1 2.2 kΩ → Q1 gate |
| Q1 gate | R2 10 kΩ → GND (pulldown) |
| Q1 source | GND |
| Q1 drain | LED cathode |
| LED anode | R3 220 Ω → +3.3 V |
| U1 pin 8 (PD1/SWIO) | WCH-LinkE SWDIO |
| U1 pin 2 (VSS) | WCH-LinkE GND |
| U1 pins 1, 3, 5, 7 | not connected |

BOM: `U1` CH32V003J4M6 · `Q1` AO3400 N-MOSFET (SOT-23) · `R1` 2.2 kΩ ·
`R2` 10 kΩ · `R3` 220 Ω · `C1` 0.1 µF · any 3.3 V LED.

Logic: low-side switch — driving PC2 **high** turns Q1 on and lights the LED.
The 10 kΩ gate pulldown keeps Q1 off while the MCU pin is floating (reset /
programming). The LED here is driven from 3.3 V through 220 Ω, so it draws
about (3.3 − Vf − Vds)/220 ≈ 5–7 mA.

Note on the power supply: the WCH-LinkE 3.3 V pin feeds the board, so the
programmer must stay connected while running. The LinkE can source only a few
tens of mA — fine for this circuit.

## 4. WCH-LinkE R0-1v3

- Enumerates as `1a86:8010` **"WCH-Link"** — this is the RISC-V (RV) mode
  firmware, correct for CH32V003. (`1a86:8012` is the ARM/DAP mode; switch
  modes with WCH-LinkUtility if the wrong ID shows up.)
- Three USB interfaces: `0` = vendor-specific programming interface used by
  `minichlink` through libusb; `1` + `2` = a CDC USB serial port that is wired
  to the target UART (optional, for `printf`).
- `minichlink -3` / `-5` / `-t` / `-f` can toggle the 3.3 V / 5 V target supply.
- Programmers supported by minichlink: WCH-LinkE, NHC-Link042, ESP32-S2
  funprog, Ardulink, rv003usb SWDIO dongle, WCH ISP bootloader.
- Bricked chip recovery: `minichlink -u` (clears all code flash).

Verified 2026-09-23 on Ubuntu 26.04 (`pvd`), toolchain at `~/Projects/ch32fun`.

| Check | Result |
|---|---|
| WCH-LinkE plugged in | yes — `1a86:8010` |
| `make`, `gcc` | **missing** |

| `libusb-1.0-0-dev`, `libudev-dev` headers | **missing** (runtime libs `libusb-1.0.so.0`, `libudev.so.1` are present) |
| `gdb-multiarch` | **missing** (only needed for GDB debugging) |
| udev rule for non-root USB access | **missing** — `/dev/bus/usb/001/019` is `root:root` |
| ch32fun checkout | `~/Projects/ch32fun` (shallow clone, commit `91032ac`, 2026-09-22) |

Install everything (one `sudo` password prompt), per the ch32fun wiki:

```sh
sudo apt update
sudo apt install build-essential libnewlib-dev gcc-riscv64-unknown-elf \
    libusb-1.0-0-dev libudev-dev gdb-multiarch
sudo cp ~/Projects/ch32fun/minichlink/99-minichlink.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Then unplug/replug the WCH-LinkE. The udev rules grant `plugdev`/`dialout`
groups `0660` access to `1a86:8010`, `1a86:8012`, ISP and USB-serial IDs.
`pvd` is already in `plugdev` and `dialout`.

Alternative without `libnewlib-dev`: ch32fun builds with `-nostdlib` and ships
`misc/libgcc.a`; the distro package is simply the tested path.

Repository: <https://github.com/cnlohr/ch32fun> (local sibling copy at
`~/Projects/ch32fun`, deliberately not committed into this repo).

`Makefile` pattern used (a sibling checkout instead of a submodule):

```make
all : flash

TARGET:=timer
TARGET_MCU?=CH32V003

CH32FUN?=../ch32fun/ch32fun
include $(CH32FUN)/ch32fun.mk

flash : cv_flash
clean : cv_clean
```

Key `make` targets (from `ch32fun/ch32fun.mk`):

| Command | Effect |
|---|---|
| `make` | build (same as `make flash`) |
| `make build` | same as `make timer.bin` — build only |
| `make flash` | build, then `minichlink -w timer.bin flash -b` |
| `make clean` | remove `timer.elf/.bin/.hex/.lst/.map` |
| `make monitor` | `minichlink -T` — printf/terminal over SWIO |
| `make gdbserver` | `minichlink -baG` (GDB server on `:3333`) |
| `make gdbclient` | `gdb-multiarch timer.elf -ex "target remote :3333"` |
| `make unbrick` | `minichlink -u` |

The first build compiles `minichlink` automatically if it is not built yet.
`minichlink` is built from `~/Projects/ch32fun/minichlink` and needs
`libusb-1.0-0-dev` + `libudev-dev`.

### ch32fun API essentials (CH32V003)

```c
#include "ch32fun.h"

SystemInit();                                        // clocks, 48 MHz PLL
funGpioInitAll();                                    // enable GPIO clock
funPinMode( pin, GPIO_Speed_10MHz | GPIO_CNF_OUT_PP ); // push-pull output
funDigitalWrite( pin, FUN_HIGH );                    // FUN_LOW to clear
Delay_Ms( 500 );
```

Pin constants are plain names: `PA1`, `PA2`, `PC1`, `PC2`, `PC4`, `PD1`, `PD6`.
`funPinMode` also accepts `GPIO_Speed_10MHz | GPIO_CNF_OUT_OD` (open drain) and
input modes; `funDigitalRead( pin )` reads a pin. `#define FUNCONF_SYSTICK_USE_HCLK 1`
in `funconfig.h` moves SysTick/Delay to the 48 MHz HCLK (default divides by 8).
`funconfig.h` is also where package defines such as `#define CH32V003J4M6 (1)`
go when an example needs package-specific behaviour.

### minichlink command reference (from source)

```
-3 Enable 3.3V            -5 Enable 5V              -t Disable 3.3V     -f Disable 5V
-k Skip programmer init   -c [port/VIDPID]          -C [programmer]      -l [USB serial]
-u Clear all code flash (unbrick)                    -E Erase chip
-a Reboot into Halt       -A Halt w/o reboot         -b Reboot out of Halt
-B Reboot into bootloader and halt                   -e Resume from halt
-i Show chip info         -s [reg] [value]  -m [reg] -g [reg]
-D NRST as GPIO           -d NRST as NRST            -N enable debug module
-P Enable read protect    -p Disable read protect    -S [flash kB] [sram kB]
-w [image] [addr]         -r [out] [addr] [size]
   addresses: flash | launcher | bootloader | option | eeprom | ram (+0x...)
-T Terminal only (must be last arg)   -G Terminal + GDB (must be last)
```

Typical first-contact test after installing the toolchain:

```sh
cd ~/Projects/ch32fun/minichlink && make
./minichlink -i          # "Found WCH-LinkE" + chip ID, proves SWIO wiring
cd ~/Projects/CH32V003-Timer && make flash
```

## 7. How the pinout was established (evidence trail)

1. WCH CH32V003 datasheet v1.8, Table 2-1 "Pin definitions" (EN + ZH) and the
   J4M6 pinout figure — source of the ambiguity described in section 2.
2. `ch32-riscv-ug/ch32-device-data` → `evidence/pins.csv` (pin table
   transcript per package) and the rendered user guide
   <https://ch32-riscv-ug.github.io/CH32V003/>.
3. `limingjie/WCH-MCU-Pinouts` clean redraws (No Remapping variant) — pins
   5/6/7/8 = PC1/PC2/PC4/PD1 in the table interpretation.
4. `mariusmym/CH32V003J4M6-Dev-Board` EasyEDA schematic — real board with
   SWIO (pin 8) brought to a 3-pin programming header, LED on PC4.
5. ch32fun `examples/tim1_phase_shifted_pwm/funconfig.h` shows the accepted
   package define style for `CH32V003J4M6`.
6. Tengo10 pinout SVG linked from the ch32fun README (note: that drawing puts
   PD1/SWIO on pin 7 — the main counter-source; hence the empirical check).
